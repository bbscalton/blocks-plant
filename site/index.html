What plant owners need under control

Blocks Plant is built around the daily frictions of a block yard — not generic inventory software.

Stockouts at the counter

Cashiers sell only what you have. Finished stock won’t go negative; low-stock signals keep 4″ / 6″ / 8″ visible before a rush empties a size.

Production you can’t see

Operators log good output from Windows or Android. Owners see today’s production and history without chasing the floor for numbers.

Materials running low

Cement, sand, aggregate, and water sit in materials inventory. Recipes (BOM) deduct raw stock when production posts — shortages are blocked with a clear error.

Unpaid customers

Cash, partial, or credit sales with customer balances. Debtors list and payment recording keep credit customers from disappearing into notebooks.

A real cashier POS

Windows desktop POS for the counter: lines, cash/credit, collect or deliver, receipts. Android offers a networked backup POS when needed.

The right people see the right screens

Owner, Cashier, and Operator roles limit prices, sales, recipes, and stock adjusts so floor staff aren’t exposed to office data.

What it manages

Products, materials, production, sales, customers, and deliveries — one API behind every client.

  • Products 4″ / 6″ / 8″ priced per block
  • POS Cash, partial, or credit
  • Production Good qty in; stock & materials update
  • Materials + recipes Receive, adjust, BOM per size
  • Finished stock Adjust + min-stock alerts
  • Debtors Balances, payments, deliveries

Roles for owner, cashier, and operator

Everyone signs in with a role. The API hides or blocks what that role should not touch.

Owner

Full plant view: dashboard, prices, stock & materials adjusts, recipes, production history, POS, debtors.

Cashier

Counter work: POS, customers, payments, sales history, deliveries. Can view materials; cannot rewrite stock or recipes.

Operator

Floor production entry and quantity views for finished stock and raw materials. No prices, sales, or balances.

Tech stack

Built as a multi-client plant system on a single .NET API.

  • API ASP.NET Core 8 · EF Core · SQLite
  • Windows POS WPF · .NET 8
  • Web dashboard Blazor Server · .NET 8
  • Android Kotlin · Jetpack Compose · Room offline queue

Prefer to run it yourself?

Clone the repo for the Windows POS, Android floor app, or a full local stack. GitHub Pages hosts this showcase only; the live URL above is the hosted web app.

  1. Start the API: cd backend then dotnet run --launch-profile http
  2. Windows POS: cd desktop then dotnet run
  3. Web dashboard: cd web then dotnet run --launch-profile http
  4. Android: open android/ in Android Studio (or build the debug APK)
